## Order (ADR)

1. **Providers** — `accelerate-data/providers` branch `sync/upstream-20261110-v0.28.0`:
   merge upstream v0.28.0 (three dependency bumps of the obot-platform/oauth2-proxy
   fork), align the fork-only `generic-oauth-auth-provider` pin, record metadata.
   Merge and let `build-vibedata-providers.yml` publish `providers-vibedata:latest`
   before the Obot image build — that build resolves `:latest` to a digest at run time.
2. **Obot reconcile** — one commit whose parent is upstream v0.28.0 and whose tree
   is upstream plus the net fork delta; then an ancestry merge with fork main whose
   tree is identical to the reconcile commit (same shape as PR #78).
3. **Obot image** — `build-vibedata-image.yml` on merge.
4. **Studio** — advance the Obot companion image pins in a separate PR.

## Risks carried to the Studio pin PR

- Upstream image moves PostgreSQL 17 → 18. Studio runs its own PostgreSQL, so check
  only that the Obot image no longer requires a client the Studio compose lacks.
- v0.28.0 does not migrate LLM gateway data (fixed in v0.28.1). Studio configures no
  model providers in Obot — no impact.
- Anonymous registry discovery becomes opt-in; message policies become disabled
  LLM-judge guardrails; `X-Obot-*` headers are reserved. Studio uses none of these.
- Upstream adds a `fetch-model-data` Docker step (`MODEL_DATA_URL`); the fork image
  build must still pass without network access to that source, or pass the arg.

## Decisions taken during the merge

- **Email linking (upstream #8415):** accepted. Identities match on provider plus
  subject only. The fork's generic-OAuth email-linking tests are removed and listed
  in `.accelerate/fork-test-removals.txt` with this reason. `TRUST_EMAIL_LINKING`
  enables nothing and its issuer-change gate is removed. Obot keeps accepting the
  setting (default `false`) because the published providers registry still requires
  it; retiring it from providers, then Obot and the Studio installers, is a follow-up.
- **mmmcp:** upstream requires mmmcp v0.2.1 (request-scoped discovery); the fork's
  mmmcp replace (partial authorization) is synced to v0.2.1 in its own fork PR. Until
  that is published, `go.mod` carries a local-path replace. After publish, the
  reconcile commit and ancestry merge are rebuilt with `commit-tree` against the
  published pseudo-version. The branch is not pushed before then.
- **`MODEL_DATA_URL`:** not passed by the vibedata image build. Without it the model
  data downloads at startup, and a failed download only warns (`modeldata.go`).
  Studio configures no LLM gateway models.
- **SvelteKit 3:** `$app/paths` no longer exports `base`; the fork's `/obot`
  base-path reroute (VD-7399) moves to the SvelteKit 3 equivalents. One
  `@ts-expect-error` that SK3 makes unnecessary is removed.
- **Gateway client trigger:** upstream `gatewayclient.New` takes an
  `mcpOAuthTokenTrigger` func; the fork keeps `mcptrigger.OwningServerTrigger`
  (VD-4889) and adapts it to that signature so keys stay namespaced and instance IDs
  resolve to their owning server.
- **Same-arity hazard:** upstream and fork `CreateMCPOAuthPendingState` take the same
  number of string parameters in different orders. Every caller was re-read and
  reordered; a type check cannot catch this.
- **Callback claim mapping:** a failed claim (`gorm.ErrRecordNotFound` or
  `ErrMCPOAuthPendingStateInvalid`) keeps the fork's 400 "invalid or expired static
  OAuth credential test" instead of upstream's raw-error 500.
- **Refresh fence:** upstream's `RefreshTokenConfig` is routed through the fork's
  catalog credential-generation fence.
- **Partial vMCP authorization (03cca2cc4):** kept. A vMCP composite with an
  unauthorized component answers 200 with an `mmmcp_auth_status` tool, so upstream
  tests expecting 401 for vMCP are adapted to the fork contract.
- **Per-request gateway token (e967c049c, 38a85aa37):** kept beside upstream's
  client-side minting; upstream handler tests that build a `Handler` directly get a
  `mintToken` stub.
- **Test harness adaptations (no production change):** upstream's postgres token
  test also migrates the fork's revoked-connection table; a composite handler test
  sets `api.Context.Request` because upstream reads the discovery revision from it;
  `NewAuthorizer` gets a nil registry-settings reader; `NewServer` loses a bool.
- **Controller fix:** a shadowed `err` in a merged controller path was corrected so
  the error is returned, not dropped.
- **New fork tests (own `*_claim_test.go` files):**
  `TestFindMCPOAuthPendingStateIgnoresClaimedState`,
  `TestCommitMCPOAuthPendingStateTokenKeepsUpstreamChallenge`,
  `TestTokenStoreRefreshTokenConfigRejectsGrantAfterCatalogCredentialChange`
  (mutation-checked: fails with the fence removed).
- **Known flake:** an LLM-gateway test is load-sensitive under the full parallel run
  and passes in isolation.
